Chaque projet que j'accepte commence de la même manière : par des repères. Non
pas par maniaquerie, mais parce que décider où vont les choses **avant** de
décider à quoi elles ressemblent économise des semaines de reprise ensuite.

## L'ordre

1. **Les lignes** — où est le contenu, où est le blanc.
2. **La grille** — colonnes, gouttières, une surface qui tient la mise en page.
3. **La typographie** — corps, graisse, coupures de ligne. Une police. Peut-être
   deux.
4. **La couleur** — papier, encre, un accent. C'est tout.
5. **Le code** — la même discipline, exprimée en composants.

Quand j'ouvre l'éditeur de code, le design est déjà décidé. La construction est
mécanique.

## Pourquoi l'ordre compte

La plupart des designers travaillent à l'envers. Ils choisissent une couleur,
trouvent une typographie, placent une image hero, puis décident où vont les
boutons. Le résultat a l'air bien jusqu'à ce que vous deviez ajouter une section
qui ne correspond pas au motif, ou une deuxième langue, ou une mise en page
mobile qui n'a jamais été envisagée.

Travailler dans l'autre sens — lignes, puis grille, puis typographie, puis
couleur, puis code — signifie que les décisions structurelles viennent en
premier. Une fois le squelette juste, tout ce qui suit est ajustement, pas
invention.

Les images, le texte, les animations — tout se glisse dans un cadre déjà conçu
pour les recevoir. Le cadre ne se bat pas avec le contenu. Le contenu ne se bat
pas avec le cadre.

## À quoi cela ressemble vraiment

Les repères sont tracés en premier. Deux lignes verticales pour les bords du
contenu. Deux lignes horizontales pour le haut du titre et la ligne de base de
la navigation. Rien d'autre n'existe encore.

La grille vient ensuite. Douze colonnes, gouttières constantes, une largeur
maximale de contenu. Ce n'est pas de la décoration — c'est une promesse sur
l'endroit où les choses vont se poser. Chaque élément qui viendra ensuite s'y
alignera, ou se déplacera pour une exception délibérée.

La typographie vient en troisième. Une seule police, choisie pour la façon dont
elle se lit aux tailles où elle sera utilisée. Coupures de ligne réglées ligne
par ligne. Le contraste de graisse n'est utilisé que là où il gagne sa place.

La couleur vient en quatrième. Papier pour le fond, encre pour le texte, un
accent pour les rares moments qui méritent l'emphase. Pas une palette — un
engagement.

Le code vient en dernier. À ce stade, tout est décidé. Les composants s'écrivent
eux-mêmes. Le CSS s'écrit tout seul. Il n'y a pas de devinette parce qu'il ne
reste rien à deviner.

## Ce que cela signifie pour le client

Vous obtenez un design qui tient. Pas seulement le jour de la livraison — un an
plus tard, quand vous devez ajouter une nouvelle page produit. Deux ans plus
tard, quand vous avez besoin d'une deuxième langue. Cinq ans plus tard, quand
vous devez le transmettre à un autre développeur.

La discipline qui entre dans la mise en page est la même discipline qui entre
dans la base de code. Une seule personne, faisant les deux, signifie que
l'intention survit à la transmission qui n'a pas lieu.

## Le point

Une bonne méthode est ennuyeuse. Elle fonctionne de la même manière à chaque
fois. Elle enlève la devinette des parties qui n'en ont pas besoin, pour que les
parties qui en ont — les idées, le texte, les moments de surprise — puissent
recevoir une véritable attention.

Les repères d'abord. Puis la grille. Puis la typographie. Puis la couleur. Puis
le code. Dans cet ordre, toujours.
