Every project I take on starts the same way: with guides. Not because I'm
precious about it, but because deciding where things go **before** you decide
what they look like saves weeks of rework later.

## The order

1. **Lines** — where is the content, where is the whitespace.
2. **Grid** — columns, gaps, a surface that holds the layout together.
3. **Type** — size, weight, line breaks. One typeface. Maybe two.
4. **Colour** — paper, ink, one accent. That's it.
5. **Code** — the same discipline, expressed in components.

By the time I open the code editor, the design is already decided. The build is
mechanical.

## Why the order matters

Most designers work the other way around. They pick a colour, find a typeface,
place a hero image, then figure out where the buttons go. The result looks fine
until you need to add a section that doesn't fit the pattern, or a second
language, or a mobile layout that was never considered.

Working in the other direction — lines, then grid, then type, then colour, then
code — means the structural decisions come first. Once the skeleton is right,
everything after it is adjustment, not invention.

The images, the copy, the animations — they all slot into a frame that was
already designed to hold them. The frame doesn't fight the content. The content
doesn't fight the frame.

## What this actually looks like

The guides are drawn first. Two vertical lines for content edges. Two horizontal
lines for the top of the headline and the baseline of the navigation. Nothing
else exists yet.

The grid comes next. Twelve columns, consistent gutters, a maximum content
width. This is not decoration — it's a promise about where things will sit.
Every element that comes later will align to it, or move to a deliberate
exception.

The type comes third. One typeface, chosen for how it reads at the sizes it will
be used at. Line breaks tuned line by line. Weight contrast used only where it
earns its place.

Colour comes fourth. Paper for the background, ink for the text, one accent for
the rare moments that deserve emphasis. Not a palette — a commitment.

Code comes last. By then, everything is decided. The components write
themselves. The CSS writes itself. There is no guessing because there is nothing
left to guess.

## What this means for the client

You get a design that holds up. Not just on the day it ships — a year later,
when you need to add a new product page. Two years later, when you need a second
language. Five years later, when you need to hand it off to another developer.

The discipline that goes into the layout is the same discipline that goes into
the codebase. One person, doing both, means the intent survives the handoff that
doesn't happen.

## The point

A good method is boring. It works the same way every time. It removes the
guesswork from the parts that don't need it, so the parts that do — the ideas,
the copy, the moments of surprise — can be given real attention.

Guides first. Then grid. Then type. Then colour. Then code. In that order, every
time.
